Docker выпустила новую версию Sandboxes — инструмента для запуска кодинг-агентов в изоляции от хост-системы. Из экспериментального превью продукт перешёл на архитектуру с **microVM-изоляцией**. Каждый агент теперь работает в отдельной виртуальной машине с собственным ядром и **гипервизорной границей** между агентом и хостом. Песочница монтирует только рабочую директорию проекта — остальная файловая система хоста агенту недоступна. Инструмент доступен на **macOS и Windows** через Docker Desktop. Поддерживаются **Claude Code, Copilot CLI, Codex CLI, Gemini CLI и Kiro**, список обещают расширять. Запуск из терминала, по документации Docker, выглядит как `sbx run claude`.

Задачу компания формулирует так: дать агенту работать **без постоянных запросов разрешений** и без риска для машины разработчика. Целью названа **автономия четвёртого уровня** — рабочие процессы выполняются без присмотра. Вместо диалоговых подтверждений границу задаёт сама виртуальная машина: агент свободен внутри и ограничен снаружи. Существующие подходы, по оценке Docker, не справляются. Изоляция на уровне ОС прерывает работу и ведёт себя по-разному на разных платформах. Контейнеры не дают агенту самому собирать и запускать Docker-образы. Полные виртуальные машины медленные для повседневной разработки. MicroVM совмещает жёсткую границу гипервизора со скоростью контейнеров — компания описывает это как **defense-in-depth**.

Отдельно решена проблема Docker-in-Docker. Агент внутри песочницы собирает и запускает контейнеры через **собственный экземпляр Docker**, работающий в той же microVM. Доступа к Docker-демону хоста у агента нет. Сетевой трафик контролируется **allow- и deny-списками**: разработчик задаёт, к каким адресам агент может обращаться. При этом песочница остаётся полноценным окружением — агент устанавливает пакеты, запускает сервисы и меняет файлы проекта.

Если агент вышел из-под контроля, песочницу удаляют и создают заново за секунды — состояние хоста не страдает. Одну песочницу можно делить между несколькими агентами, чтобы они работали в общем окружении. В планах — поддержка Linux, интеграция с **MCP Gateway**, проброс портов между песочницей и хостом, доступ к сервисам хоста и новые агенты. Разработчик Matt Pocock назвал Sandboxes лучшим по удобству локальным решением для песочниц среди опробованных.
